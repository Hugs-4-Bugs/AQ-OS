# AcquisitionOS — Founder Handover Checklist (KT)

> **Purpose:** everything to transfer if/when the founder leaves. Work top-to-bottom; every item is an actionable checkbox.
> **Last updated: 2026-09-09**
> **Companion docs:** `docs/kt/CODEBASE-OVERVIEW.md` (how the code works), `docs/kt/VENDOR-CONTACTS.md` (every external service + rotation calendar).

**Ground rule for this document:** no secret values are ever written here — only env var **names** and where they live. Actual values exist in exactly three places (see §3): the platform **secrets panel**, the sandbox **`.env`** (auto-regenerated by `ensure-env.sh`), and the **password manager** (if the founder maintains one — MUST be confirmed, see §1.0).

## 3. Credential management procedure (the operating manual)

- [ ] **`ensure-env.sh` is the source of truth for `.env`.** The sandbox periodically wipes `.env`; the keepalive job re-runs the script, which rewrites the base template **and re-appends preserved secrets** (`SMTP_PASSWORD`, `SMTP_PASS`, `GMAIL_APP_PASSWORD`, `GMAIL_PASSWORD`, `RESEND_API_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`). Any new persistent secret MUST be added to that `PRESERVE_KEYS` list (or the template) or it will silently vanish.
  - ⚠️ Known debt: `ensure-env.sh` currently embeds some credential **values inline** in the template (repo-local, chmod 600, but git-trackable). Rotating those into the secrets panel only is tracked in §6 tech debt.
- [ ] **Secrets panel** = the injected-deployment source. Names must match code exactly; the app logs `SET/MISSING` per alias at boot (`instrumentation.ts` + `[SMTP-Env-Diag]`) — values are never logged.
- [ ] **Password manager** = the human recovery copy. Reconcile it against `docs/04-secrets-and-configuration/ALL-SECRETS.md` during handover.
- [ ] **Rotation steps** (any var): vendor console → new value → update secrets panel → update `ensure-env.sh` (template or preserve list) → let keepalive rebuild `.env` → verify: `tail dev.log` for `[SMTP-Env-Diag]`, `curl localhost:3000/api/auth/config` expect `{"googleAvailable":true,"emailConfigured":true}` → run one end-to-end action (magic-link request) before closing.
- [ ] **Aliases matter:** SMTP vars have 7 user-aliases and 9 password-aliases (see `src/lib/email-ethereal.ts`). Always read via the helpers (`getSmtpUser()` / `getSmtpPassword()`), never `process.env.SMTP_PASS` directly (that's the historical notification-engine bug — §6).
- [ ] **Never** commit secret values to git, paste them into chat, or print them in logs — the codebase convention is SET/MISSING only.

## 4. Ongoing operational tasks (must survive handover)

- [ ] **Keepalive cron — Job 304271, every 5 min** (platform scheduler, Asia/Calcutta): runs `keepalive-v2.sh`, which is **health-check based** — healthy server (HTTP 200 + `/api/auth/config` green + `.env` has `GOOGLE_CLIENT_ID`) → does NOTHING; unhealthy → restores `.env` via `ensure-env.sh`, re-disables `src/middleware.ts`, restores the SWC binary, restarts `next dev -p 3000`. ⚠️ Do not revert to a blind-restart script (that caused the "app changes every 3 minutes" incident of 2026-09).
- [ ] **API key expiration cron — Job 161223, hourly**: pings `/api/cron/expire-api-keys` (Bearer `CRON_SECRET`). Known flaky when the server was unstable; standalone fallback script `cron-expire-api-keys.ts` exists.
- [ ] **webDevReview cron — Job 370376, every 15 min** (platform review loop; older worklog entries logged the same function as Job 286616 — re-verify the live ID in the scheduler after handover): continuous assess/fix/extend loop. Confirm the new owner's account keeps it firing.
- [ ] **Monitoring `dev.log`**: the dev server writes here (`next dev … | tee dev.log`). First diagnostic for everything. Watch for: `[SMTP-Env-Diag]` alias lines, `redirect_uri_mismatch`, `535` SMTP auth, quota 429s, sandbox kill messages, and impossible syntax errors (= source corruption; run `python3 scripts/repair-corruption.py` — see `docs/kt/CODEBASE-OVERVIEW.md` §9a).
- [ ] **Cron HTTP routes** (all require `Authorization: Bearer $CRON_SECRET`), currently scheduled via the platform jobs above: `autonomous-outreach`, `credit-renewal`, `end-of-period`, `expire-api-keys`, `hot-lead-scan`, `meeting-reminders`, `payment-reconciliation`, `process-gmail-replies`, `process-sequences`, `renew-subscriptions`, `sdr-cycle`, `sequence-processing`. If platform scheduling ever stops, these are the endpoints to move to any external scheduler.
- [ ] **Backup**: `bun run backup` (`scripts/backup/backup.sh`) + restore via `backup:restore`; SQLite file `db/custom.db` is per-deployment — schedule regular copies off-box.
- [ ] **Server restart policy**: never `bun run build` in-sandbox (OOM) and never run `bun run dev` manually while keepalive is healthy.

## 11. Day-0 incident runbook (pin this)

| Symptom | First action | Then |
|---|---|---|
| App down (no HTTP on :3000) | `bash keepalive-v2.sh`; wait 25 s | If still down: `tail -100 dev.log`; check disk/memory; re-run once |
| `.env` missing/wiped | `bash ensure-env.sh` | Verify `PRESERVE_KEYS` still lists your secrets; curl `/api/auth/config` |
| Login emails not sending | `tail dev.log` → `[SMTP-Env-Diag]` | Missing alias → secrets panel + `ensure-env.sh`; `535` → rotate app password |
| `redirect_uri_mismatch` | Add current public origin to GCP OAuth client | `https://<domain>/api/auth/callback/google`; retest consent |
| AI actions failing | `tail dev.log` → provider chain logs | Check Z-AI panel quota; optionally set `OPENAI_API_KEY` stopgap |
| Impossible syntax errors in tsc/next | Assume source corruption | Re-read file, `git show HEAD:<path>`, run `scripts/repair-corruption.py`, round-trip verify |
| "App changes every few minutes" | Check keepalive is health-check version | Then check corruption (above); review last git commits for parallel agent sessions |
| Cron automations stopped | Verify platform scheduler jobs firing | Fallback: call `/api/cron/*` with `Authorization: Bearer $CRON_SECRET` from any scheduler |
| Checkout 500 "Stripe is not configured" | Expected until keys exist | Follow VENDOR-CONTACTS §5.4 go-live checklist |
| DB locked / slow writes | Expected SQLite behavior at scale | Prioritize ADR-012 PostgreSQL migration; avoid bulk writes in peak hours |
