- src/lib/admin-guard.ts: Removed auto-update of lastActivityAt on every
  page navigation. The guard now READS lastActivityAt for enforcement
  only. Activity updates are accepted exclusively via the new
  POST /api/auth/activity endpoint (called by the client on genuine
  user input). This converts the timeout from a "10-min absolute
  session lifetime if user stays on one page" into a TRUE inactivity
  timeout - admins can actively use the console for 30+ minutes
  without forced logout, and 10 minutes of genuine inactivity expires
  the session.
- src/app/api/auth/activity/route.ts (NEW): Server-side activity
  heartbeat. Authenticates via access_token cookie, resolves the
  UserSession via refresh_token cookie, validates session is not
  revoked/expired, updates lastActivityAt THROTTLED to one DB write
  per 30s per session. CRITICAL: rejects pings on already-expired
  sessions with 401 + SESSION_EXPIRED_INACTIVITY and revokes the
  session - stale tabs cannot extend expired sessions.
- src/app/api/auth/session-status/route.ts (NEW): Read-only endpoint
  returning authoritative secondsLeft, lastActivityAt, role, mfaVerified.
  Polling this endpoint does NOT extend the session (read-only).
- src/components/admin/admin-inactivity-timer.tsx: Rewritten to listen
  to genuine user activity (mousedown, keydown, touchstart, pen
  pointerdown - NOT mousemove/pointermove which fire without intent).
  Client-side ping throttle: 15s. Server-side status poll: every 10s.
  Smooth local countdown between polls. Force logout on secondsLeft=0
  or 401 from server. Visibilitychange handler re-syncs immediately
  when tab becomes visible (server may return 401 if expired during
  hidden period - logged out then). Background polling, token refresh,
  React re-renders, and network traffic do NOT reset the timer.

ISSUE 7 (Admin API 401 failures - root cause diagnosed):
- Root cause 1 (critical regression): Commit 47b3ce842 removed the
  useTokenRefresh import line from admin-nav.tsx but LEFT the
  useTokenRefresh() call at line 46. This caused a ReferenceError at
  runtime, breaking the entire AdminNav render and silently killing
  the 14-minute token refresh - leaving admin APIs returning 401 after
  the 15-minute access token expired.
  Fix: restore the import (and add the additional admin fields used
  by the new profile menu).
- Root cause 2 (schema drift): The AuditLog table in the dev DB was
  missing 10 columns that exist in the Prisma schema (sequence,
  previousHash, eventHash, severity, requestId, outcome, beforeState,
  afterState, securityEventType, confirmed). When the
  /api/admin/security/audit endpoint tried to SELECT these columns,
  Prisma threw a 500. Fix: scripts/add-audit-columns.py applies a
  safe additive ALTER TABLE migration (forward-only, no data loss,
  all columns are optional in schema - existing rows get NULL).
