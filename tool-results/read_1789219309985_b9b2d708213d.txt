   908→(a Nodemailer test sink at ethereal.email). Ethereal "delivers" messages to a
   909→private test mailbox and returns a preview URL — but those messages NEVER reach
   910→a real user inbox. End users therefore never receive magic links or OTP codes,

   914→Resend key NOR real SMTP credentials are detected by the provider-selection

   951→
   952→`isRealSmtpConfigured()` (email-ethereal.ts:99-108) requires ALL of:
   953→  - `SMTP_HOST`   present

   955→  - `getSmtpUser()`     non-empty AND not a placeholder   (`SMTP_USER || GMAIL_USER`)

   957→
   958→`isPlaceholderValue()` (email-ethereal.ts:87-92) flags values that are empty,
   959→equal to `"placeholder"`, or start with `"your-"`.
   960→
   961→`isRealResendConfigured()` (email-ethereal.ts:62-65) requires `RESEND_API_KEY`
   962→to be present AND NOT start with `re_your-`.

   964→On the deployed platform, the startup banner reports SMTP as not configured

   969→    (or their GMAIL_* aliases) is unset or a `your-…`/`placeholder` value.

   976→## THE "DEGRADED — Missing/degraded: SMTP From" WARNING
   977→
   978→- Source: `src/lib/env-safeguard.ts:283` —
   979→  `console.warn('DEGRADED — Missing/degraded: ' + report.degraded.join(', '))`
   980→- `SMTP_FROM` is registered at `env-safeguard.ts:52` with `degrades: true`,

   983→IMPORTANT NUANCE: `SMTP_FROM` missing is a RED HERRING for the Ethereal
   984→fallback. `isRealSmtpConfigured()` does NOT check `SMTP_FROM` — only HOST/PORT/
